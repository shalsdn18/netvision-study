## User Scenarios & Testing *(mandatory)*

### User Story 1 - 카메라 등록 및 관리 (Priority: P1)

관리자는 카메라 ID, 카메라 이름, IP 주소를 등록하고 등록된 카메라를 목록 또는 상세 화면에서 확인하며, 이름과 IP 주소를 수정하거나 더 이상 사용하지 않는 카메라를 삭제할 수 있다.

**Why this priority**: 카메라를 관리할 대상이 없으면 상태 진단을 포함한 나머지 기능을 사용할 수 없으므로 핵심 흐름이다.

**Independent Test**: 유효한 카메라를 등록한 뒤 목록과 상세 조회, 수정, 삭제를 순서대로 수행하여 각 결과가 저장된 정보와 일치하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 등록되지 않은 고유한 카메라 ID와 유효한 이름 및 IP 주소가 있을 때, **When** 사용자가 카메라 등록을 요청하면, **Then** 시스템은 카메라를 저장하고 생성된 카메라 정보를 반환한다.
2. **Given** 하나 이상의 카메라가 등록되어 있을 때, **When** 사용자가 카메라 목록을 요청하면, **Then** 시스템은 등록된 카메라들을 반환한다.
3. **Given** 카메라가 등록되어 있을 때, **When** 사용자가 카메라 ID로 상세 조회를 요청하면, **Then** 시스템은 해당 카메라의 ID, 이름, IP 주소를 반환한다.
4. **Given** 카메라가 등록되어 있을 때, **When** 사용자가 이름 또는 IP 주소를 수정하면, **Then** 시스템은 변경 사항을 저장하고 최신 정보를 반환한다.
5. **Given** 카메라가 등록되어 있을 때, **When** 사용자가 카메라 삭제를 요청하면, **Then** 시스템은 해당 카메라를 삭제하고 이후 조회에서 찾을 수 없도록 한다.

---

### User Story 2 - 네트워크 연결 진단 (Priority: P2)

관리자는 등록된 카메라의 IP 주소에 Ping 테스트를 수행하고 지정한 TCP 포트의 연결 가능 여부를 확인하여 카메라의 네트워크 상태를 진단할 수 있다.

**Why this priority**: 등록된 카메라가 실제로 연결 가능한지 확인해야 관리자가 장애를 빠르게 판단할 수 있다.

**Independent Test**: 등록된 카메라에 대해 Ping과 TCP Port 확인을 각각 요청하고, 연결 가능·불가·응답 시간 초과 상태가 구분되어 반환되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 유효한 IP 주소를 가진 카메라가 등록되어 있고 대상이 응답할 때, **When** 사용자가 Ping 테스트를 요청하면, **Then** 시스템은 성공 상태와 측정 결과를 반환한다.
2. **Given** 카메라의 IP 주소가 응답하지 않을 때, **When** 사용자가 Ping 테스트를 요청하면, **Then** 시스템은 실패 또는 시간 초과 상태를 반환하고 API 요청 자체는 명확한 오류 없이 완료한다.
3. **Given** 카메라가 등록되어 있고 유효한 TCP 포트가 지정될 때, **When** 사용자가 TCP Port 연결 확인을 요청하면, **Then** 시스템은 연결 가능 여부와 진단 결과를 반환한다.
4. **Given** 유효하지 않은 포트가 지정될 때, **When** 사용자가 TCP Port 연결 확인을 요청하면, **Then** 시스템은 입력 오류를 일관된 오류 형식으로 반환한다.

---

### User Story 3 - 예외 상황 처리 (Priority: P1)

관리자는 잘못된 입력이나 존재하지 않는 카메라를 요청했을 때 원인을 이해할 수 있는 일관된 응답을 받아 잘못된 작업과 시스템 상태를 구분할 수 있다.

**Why this priority**: 입력 오류와 대상 부재를 명확히 처리해야 데이터 손상과 운영 혼란을 방지할 수 있다.

**Independent Test**: 잘못된 IP 주소, 중복 카메라 ID, 존재하지 않는 카메라 ID를 사용해 등록·조회·수정·삭제·진단 요청을 실행하고 각각 적절한 오류 결과를 확인한다.

**Acceptance Scenarios**:

1. **Given** IP 주소 형식이 올바르지 않을 때, **When** 사용자가 등록 또는 수정 요청을 보내면, **Then** 시스템은 저장하지 않고 어떤 입력이 잘못되었는지 설명하는 입력 오류를 반환한다.
2. **Given** 이미 등록된 카메라 ID가 있을 때, **When** 사용자가 같은 ID로 등록을 요청하면, **Then** 시스템은 기존 카메라를 변경하지 않고 중복 오류를 반환한다.
3. **Given** 요청한 카메라 ID가 존재하지 않을 때, **When** 사용자가 조회 또는 수정 요청을 보내면, **Then** 시스템은 대상 없음 오류를 반환한다.
4. **Given** 요청한 카메라 ID가 존재하지 않을 때, **When** 사용자가 삭제 또는 네트워크 진단을 요청하면, **Then** 시스템은 대상 없음 상태를 반환하고 진단을 수행하지 않는다.

### Edge Cases

- 카메라 이름이 비어 있거나 허용된 길이를 초과하면 등록 및 수정이 거부된다.
- 카메라 ID가 비어 있거나 형식에 맞지 않으면 등록 및 식별자 기반 요청이 거부된다.
- IPv4 주소가 아닌 값, 범위를 벗어난 옥텟, 공백이 포함된 값은 유효한 IP 주소로 처리하지 않는다.
- 목록에 카메라가 없으면 빈 목록과 정상적인 목록 응답을 반환한다.
- 빈 요청 본문, 필수 필드 누락, 예상하지 못한 필드 형식은 입력 오류로 처리한다.
- Ping 또는 TCP 연결 확인이 정해진 진단 시간 안에 끝나지 않으면 시간 초과 결과를 반환하고 요청이 무기한 대기하지 않도록 한다.
- TCP 포트는 1부터 65535 사이의 정수만 허용한다.
- 동시에 같은 카메라를 수정하거나 삭제하는 요청이 충돌할 경우 저장된 정보가 부분적으로 손상되지 않아야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 Camera ID, Camera Name, IP Address를 포함한 카메라 등록을 제공해야 한다.
- **FR-002**: 시스템은 등록 시 Camera ID의 고유성, Camera Name의 필수 여부와 허용 길이, IP Address의 IPv4 형식을 검증해야 한다.
- **FR-003**: 시스템은 등록된 모든 카메라의 목록 조회와 Camera ID를 통한 상세 조회를 제공해야 한다.
- **FR-004**: 시스템은 등록된 카메라의 Camera Name과 IP Address를 수정할 수 있도록 해야 하며, 수정 시에도 모든 입력 검증을 적용해야 한다.
- **FR-005**: 시스템은 Camera ID를 기준으로 카메라를 삭제할 수 있도록 해야 하며, 삭제되지 않은 다른 카메라에는 영향을 주지 않아야 한다.
- **FR-006**: 시스템은 등록된 카메라의 IP Address를 대상으로 Ping 테스트를 제공해야 한다.
- **FR-007**: 시스템은 등록된 카메라와 지정된 TCP Port 사이의 연결 가능 여부를 확인하는 진단을 제공해야 한다.
- **FR-008**: 시스템은 Ping 및 TCP 연결 진단 결과를 성공, 실패, 시간 초과 중 하나 이상으로 구분하여 반환해야 한다.
- **FR-009**: 시스템은 존재하지 않는 Camera ID에 대한 조회, 수정, 삭제, Ping, TCP Port 확인 요청을 대상 없음 오류로 처리해야 한다.
- **FR-010**: 시스템은 잘못된 IP 주소, 잘못된 포트, 필수값 누락, 형식 오류를 저장 또는 진단 전에 거부해야 한다.
- **FR-011**: 시스템은 중복 Camera ID 등록을 거부하고 기존 카메라 정보를 변경하지 않아야 한다.
- **FR-012**: 시스템은 모든 성공 및 오류 응답에 일관된 HTTP 상태와 JSON 응답 형식을 사용해야 한다.
- **FR-013**: 오류 응답은 안정적인 오류 코드와 사람이 이해할 수 있는 메시지를 포함해야 하며 내부 정보나 민감한 정보를 노출하지 않아야 한다.
- **FR-014**: 시스템은 목록에 카메라가 없을 때 빈 목록을 정상 응답으로 반환해야 한다.
- **FR-015**: 각 기능 요구사항은 자동화된 테스트 또는 재현 가능한 검증 절차로 확인할 수 있어야 한다.
- **FR-016**: 시스템은 등록된 카메라 정보가 API 프로세스 재시작 후에도 유지되도록 영구 보존해야 한다.
- **FR-017**: 시스템은 TCP Port 연결 확인 요청마다 사용자가 제공한 포트 번호를 사용해야 하며, 카메라 정보에 기본 포트를 저장하지 않아야 한다.
- **FR-018**: 시스템은 Ping 및 TCP Port 연결 확인을 각각 3초 이내에 완료하지 못하면 시간 초과 결과로 반환해야 한다.

### Key Entities *(include if feature involves data)*

- **Camera**: 관리 대상 IP 카메라를 나타내며 고유한 Camera ID, Camera Name, IP Address를 가진다.
- **Network Diagnostic Result**: 특정 카메라와 진단 종류에 대한 성공·실패·시간 초과 상태 및 진단 결과를 나타낸다.
- **API Error**: 요청 실패 원인을 나타내는 안정적인 오류 코드, 메시지, 선택적 필드 오류 정보를 포함한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 유효한 카메라 등록, 목록 조회, 상세 조회, 수정, 삭제의 각 요청은 자동화된 검증에서 100% 기대한 상태와 응답 형식을 반환한다.
- **SC-002**: 잘못된 IP 주소, 중복 ID, 존재하지 않는 카메라, 잘못된 포트에 대한 오류 사례가 테스트에서 100% 저장 또는 진단 없이 거부된다.
- **SC-003**: Ping 및 TCP Port 진단 요청의 100%가 성공, 실패, 시간 초과 중 판별 가능한 결과를 반환하며 무기한 대기하지 않는다.
- **SC-004**: 정상적인 네트워크 환경에서 유효한 관리 요청의 95%가 1초 이내에 사용자에게 결과를 제공한다.
- **SC-005**: 신규 사용자가 문서만 참고하여 카메라 1대를 등록하고 상태 진단까지 수행하는 시나리오를 첫 시도에 완료할 수 있다.
- **SC-006**: 핵심 API 동작과 예외 상황에 대한 자동화 테스트가 표준 테스트 실행으로 반복 가능하게 통과한다.

## Assumptions

- 시스템의 주요 사용자는 카메라를 등록하고 운영 상태를 확인하는 관리자이다.
- MVP에서는 사용자 인증과 권한 관리를 범위에 포함하지 않는다.
- MVP에서는 Camera ID가 요청자가 제공하는 고유 식별자이며 자동 생성 요구는 없다.
- 카메라 정보는 API 프로세스 재시작 후에도 보존되어야 한다.
- IP Address는 IPv4 주소를 기본 지원하며 호스트명과 IPv6 지원은 범위에 포함하지 않는다.
- TCP Port 번호는 카메라별 저장값이 아니라 각 진단 요청에서 제공된다.
- Ping 및 TCP Port 확인의 대상은 시스템이 실행되는 네트워크에서 접근 가능해야 한다.
- Ping 및 TCP Port 연결 확인의 시간 제한은 각각 3초이다.
- 데이터 보존, 감사 로그, 카메라 영상 스트리밍, 알림, 일괄 등록 및 검색·정렬은 이 기능의 범위에 포함하지 않는다.
